# Software Factory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace cross-model-dev, the task-board mod and xagent's routing with a `/factory` skill: Opus spec → Codex Sol build → four free DeepSeek reviews → Opus gate → PR to `dev`, one worktree per job, plus a cleanup that runs post-merge steps on dev and prod.

**Architecture:** xagent shrinks to one `dispatch` tool with two backends (codex, opencode) and gains `outputFile` and `network`. The factory is a personal skill (`skills/factory/`) whose orchestrator runs native Opus subagents (`agents/`) and dispatches Codex/opencode with prompt files in `skills/factory/prompts/`. Each target repo describes itself in a `## Factory` section of its CLAUDE.md.

**Tech Stack:** Claude Code mods (TypeScript, `claude plugin test`, bun), markdown skills/agents, opencode 1.18, codex-cli 0.163, gh, git worktrees, Docker (`pgvector/pgvector:pg17`), agent-browser.

**Spec:** `docs/specs/2026-10-19-factory-design.md`. Base material: `zazencodes-season-3/src/software-factory-claude-code` (clone it to `/tmp/recon-sf` with a sparse checkout if it's gone).

## Global Constraints

- The factory never merges, and never pushes `dev` or `main`. It pushes only `factory/<job-id>`.
- No mention of Claude, Codex, DeepSeek, opencode, Anthropic, AI, or a Co-Authored-By trailer in any commit, branch, PR title or PR body the factory makes. This also applies to the commits made while carrying out this plan.
- Fixed models:

  | Role | Backend | Model | Setting |
  |---|---|---|---|
  | builder | codex | `gpt-6.1-sol` | effort `high`, `network: true`, `timeoutMs: 3_600_000` |
  | reviewers | opencode | `opencode/deepseek-v4.1-flash-free` | variant `max`, agent `factory-reviewer` |
  | spec-writer, approver | native subagents | opus | — |

- No fallback model, ever. A failed or refused dispatch stops the job (`needs-human`).
- Worktrees branch from `origin/dev` after `git fetch origin dev`. Diffs use `origin/dev...factory/<job-id>`.
- State lives in `<repo>/.factory/`, which is added to `.git/info/exclude`.
- Never touch the main checkout's working tree or HEAD. Never `git stash`, `git clean`, `pkill -f` or `prisma migrate dev`. Stop processes by their own PID.
- Production steps run only after the owner's in-session yes, one per job.
- `MAX_RESUMES = 2`.

## Review Focus

1. **A reviewer changes files in the worktree** despite the agent rules. The orchestrator's post-round `git status --porcelain` check must catch it and set `needs-human`. Covered in Task 6 (orchestrator rule) and the Task 9 smoke run (a planted change).
2. **Two sessions start jobs at the same moment.** Claiming a job with `mkdir` (no `-p`) must give each a distinct id, and free-port picking must not hand both the same port. Covered in Task 6 (ports go through `job.json` of all jobs) and Task 9 (two sessions started back to back).
3. **A free DeepSeek run fails or answers with no verdict line** (rate limit, empty output). It gets one rerun, then `needs-human`. It never falls back to another model. Covered in Task 2 (`opencode` error parse test) and Task 6.
4. **The builder's session can't be resumed** (an expired codex session). Start a fresh session with the review paths and say so. Covered in Task 6.
5. **The PR step fails** (no remote, gh auth, or the branch already has a PR). Set `needs-human` with gh's message, and keep the branch. Covered in Task 9 (the scratch repo has no GitHub remote).

### Task 6: The orchestrator skill

**Files:**

**Interfaces:**
- Consumes:
  - `mcp__xagent__dispatch` with `outputFile`, `network` and `agent` (Task 2)
  - the agents (Task 3), the prompts (Task 4), the `## Factory` section (Task 5)
- Produces:

    - `/factory next`
    - `/factory approve <job-id>`
    - `/factory rework <job-id> <note>`

    { "id", "feature", "branch", "worktree", "stage", "round",
      "reviews": {"security","ux","ui","code"},

- [ ] **Step 1:** Start from the original `SKILL.md`, then write these sections. Their behaviour comes from the spec's sections of the same names; don't restate the spec in prose, just make each step exact.
  1. **Preflight.**
     - Find `## Factory` in CLAUDE.md or AGENTS.md. If it's missing, refuse and name the missing section.
     - Add `.factory/` to `.git/info/exclude` if it isn't there.
     - Run `git fetch origin dev`.
  2. **Create the job.**
     - Claim the id with `mkdir` (no `-p`) under `.factory/jobs/`.
     - Pick the worktree path `<parent>/<name>-factory/<job-id>`.
     - Pick `port` and `dbPort`: the lowest free ports from 5200 up that are not in any `.factory/jobs/*/job.json` across the three repos. Test them with `ss -ltn`.
  3. **Worktree.**
     - `git worktree add -b factory/<job-id> <wt> origin/dev`.
     - Symlink the Env links, then run Setup.
     - If anything fails, set `needs-human`.
  4. **Spec.** Run `Agent(subagent_type: spec-writer)`.
  5. **Build.**
     - Dispatch with: codex, `gpt-6.1-sol`, `high`, `write`, `network: true`, `dir: <wt>`, `timeoutMs: 3600000`, `outputFile: <job>/build.md`, prompt = `prompts/builder.md` + paths.
     - Store `sessionId` as `builderSession`.
     - Read only line 1 of `build.md`.
     - On READY with changes, run `git -C <wt> add -A && git -C <wt> commit -m "<Summary line>"`.
     - READY with no changes means `needs-human` ("builder changed nothing").
  6. **Review round N.**
     - Start Review DB (ERP), then Dev server in the background on `port`. Record the PID and wait for the readiness URL.
     - Make four `dispatch` calls in one message, each with: opencode, the DeepSeek model, `max`, `read-only`, `agent: factory-reviewer`, `dir: <wt>`, and `outputFile: <job>/round-<N>/review-<role>.md`.
     - Update `job.json` as each one lands, reading only line 1.
     - A failed dispatch or a missing verdict gets one rerun, then `needs-human`.
     - After all four: `kill <pid>`, and confirm it's gone with `kill -0`. Then run `git -C <wt> status --porcelain`; any output means `needs-human` ("reviewer changed the worktree"), and nothing is discarded.
  7. **Fix loop.**
     - Resume `builderSession` with `Round N reviews are in <job>/round-<N>/. Address every VERDICT: CHANGES review, then give the full build.md for round N+1.` and the same `outputFile`.
     - If the resume fails as unknown or expired, start a fresh dispatch with the same text plus "Read spec.md first.", and tell the owner.
     - With no resumes left, write the ESCALATE `decision.md` as in the original.
  8. **Approve.** Run `Agent(subagent_type: approver)`, then read line 1.
  9. **Open PR.**
     - `git -C <wt> push -u origin factory/<job-id>`.
     - If `pr` is already set, stop here: the push updates the existing PR.
     - Otherwise run `gh pr create --base dev --head factory/<job-id> --title <feature summary> --body-file <tmp>`. The body has these sections: Summary (from spec.md), Reviews (the four verdicts), Gate (line 2+ of decision.md), and Post-merge steps (copied from build.md).
     - Grep the body for "claude|co-authored|generated with|anthropic|codex|deepseek|opencode" (case-insensitive) before creating it. A hit gets removed.
     - Set `stage: pr-open` and `pr: <url>`.
  10. **`/factory approve`, `/factory rework`.** Same as the original, plus:
      - `rework` is also allowed from `pr-open`.
      - Rework resumes `builderSession`, falling back to a fresh session as in 7.
  11. **`/factory cleanup`.** This is the spec's "Post-merge steps and `/factory cleanup`" section, step by step:
      - Use `gh pr view <pr> --json state,mergeCommit`.
      - Check Deploy Dev with `gh run list --commit <sha> --workflow` (find the workflow name in `.github/workflows`).
      - Check migrations with `ssh dev-apps 'docker exec replacenc-erp node node_modules/prisma/build/index.js migrate status'`.
      - Check that the merge reached main with `git merge-base --is-ancestor <sha> origin/main`, then the prod deploy run.
      - Run prod steps only after the owner says yes, once per job.
      - Finish with `docker rm -f <job-id>-db`, `git worktree remove`, and `git branch -D factory/<job-id>`.
  12. **Reporting.** One line per transition, as in the original.
  13. **Never.**
      - merge
      - push `dev` or `main`
      - use another model when a dispatch fails
      - `git stash` or `git clean`
      - `pkill -f`
      - `prisma migrate dev`
      - run prod steps without the in-session yes
      - read review or build files past line 1, unless reporting a `needs-human` reason to the owner
